The Issue: serves as the initial project management ticket. It defines the goal, requirements, and acceptance criteria for a specific problem or feature before any development begins. 
The Feature Branch: provides an isolated, parallel workspace spun off from the stable default branch. This ensures that live project code remains entirely uncompromised while new changes are actively developed.
Commits: act as granular, descriptive snapshots taken along the development branch timeline, serving as a progress log and version check system.
The Pull Request(PR):  bridges the gap between isolation and collaboration. It formally proposes moving the finalized work from the feature branch back into the default branch.
The Review: happens directly within the PR interface. It acts as a mandatory quality gate where peers or developers critique the changes against the original issue's acceptance criteria.
